## 1. 目的と成功の定義

**ブライダルの価値を上げる。結婚式からこの国を元気にする。**

Dolphin CREATE は、新規接客で分かった新郎新婦の選択理由を匿名集計し、会場の実際の強みを広告へ反映する。広告接触から予約・来館・成約までを結び、クリックの多さではなく、良質な来館と成約で施策を評価する。

| 担当 | 役割 |
|---|---|
| Aさん（マーケ・データ） | ブライダルマーケティング、データ設計、AI分析、媒体・計測連携、優先順位と効果判定を統括 |
| Bさん（制作・ブランド） | 画像選定、コピー、媒体別の表現、ブランド品質、広告制作の検証を統括 |
| 会場担当 | 施設情報・価格・特典・空き状況・素材利用権と公開可否を承認 |
| 本部管理者 | アカウントと権限の管理（承認はしない） |

- **主KPI**：有効予約数・有効予約単価、来館数・来館単価、成約数・成約単価
- **副KPI**：売上、粗利、粗利ROAS、予約→来館率、来館→成約率、広告とLPの一致率
- **診断指標**：CTR、CPC（これだけで成功と判定しない）

## 3. 利用者と権限

アカウントは施設コードに属し、権限と見られる施設を持つ。会場担当は自施設に固定し、本部のアカウントだけが複数施設を見られる。

| 権限 | 所属 | 見られる施設 | 承認できること | アカウント管理 |
|---|---|---|---|---|
| 本部管理者 | 本部 | 全施設 | なし | 発行・変更・停止・再発行・ロック解除 |
| マーケ・データ（Aさん） | 本部 | 担当する施設 | データ・計測の承認 | なし |
| 制作・ブランド（Bさん） | 本部 | 担当する施設 | 表現・ブランドの承認、素材の権利確認 | なし |
| 施設管理者（本番で追加） | 各施設 | 自施設のみ | 事実・素材・予算の承認、月間予算上限の設定 | 自施設の担当者の発行・停止 |
| 会場担当 | 各施設 | 自施設のみ | 事実・素材・予算の承認 | なし |
| 閲覧のみ（本番で追加） | 各施設 | 自施設のみ | なし | なし |

1人が複数の権限を持つ場合でも、承認欄の2つ以上を同じ人が承認できないようにする。

**クリエイティブ作成**
- **Dolphin生成画像の取込**：画像ファイルと、任意の情報CSV（file_name、asset_id、title、prompt、target、rights、expiry）を取り込む。取り込んだ画像は「権利確認中・未承認」から始まり、Bさんの権利確認と会場担当の承認を経て広告に使える。「生成→権利確認待ち→承認待ち→使える」の件数を表示する。
- **画像×キャッチの組み合わせ**
  - 画像の候補：成約群の選択率の差が大きい順に並べる
  - キャッチの候補：Dolphinの提案コピー、既存の案のキャッチ、AI案（5案）
  - 編集できる項目：キャッチ・サブコピー・ボタン文言、文字の位置（下・中央・左・上）、書体（明朝・ゴシック）、文字色、サイズ（Instagramフィード4:5、ストーリーズ9:16、正方形1:1、Googleディスプレイ1.91:1）
  - 自動の付加：生成画像には「※写真はイメージです」を自動で入れる。未承認の素材には「下書き・未承認素材」の透かしを入れる
  - 簡易チェック：素材の権利、キャッチ15字・サブ24字の目安、施設事実の裏付け、条件表記、画像とコピーの訴求の一致
  - おすすめの組み合わせ：使える画像と、裏付けのあるコピーの上位6案を自動で作る
  - 出力：PNG保存、または「Instagram広告の案にする」（公開前チェックと承認へ）

## 6. データと処理の流れ

1. 同意を確認し、Dolphin の音声または既存の分析JSONと予約データを取得する。原音声の保存期間とアクセス権を設定する。
2. 話者分離、文字起こし、氏名・連絡先等のマスキングを行う。各抽出項目に話者・時刻・引用箇所・確度・明示/推測の別を付ける。
3. consultation_id／lead_id と予約・来館・成約を照合する。施設・期間単位で匿名集計し、成約群と非成約群の差を出す。
4. 承認済みの会場情報・素材・料金条件と集計インサイトから広告仮説を作る。Bさんが表現案を制作する。
5. 施設事実・画像の権利・媒体仕様・広告とLPの整合・計測URL・予算を機械検査し、3者が承認する。
6. 媒体用CSVに書き出す（第2段階で媒体APIへの作成/更新）。冪等キーで重複を防ぎ、開始・停止・予算上限を記録する。
7. Google広告／Meta から費用・配信指標を、GA4 からLP・予約行動を、CRM から来館・成約を取得し、同じ lead_id に結合する。
8. 週次で予約品質と成約を確認し、画像・コピー・検索語ごとに継続/修正/停止/保留を提案する。承認後に反映する。
9. 画像・広告別の成果をDolphinへ返し（⑩）、次の提案に使う。

**識別の核心**：広告クリック時のUTM・クリックID・GA4 client_id を、フォーム送信時に lead_id とともに保存する。電話・外部予約サイトなどは別の受け渡し設計が必要。予約後の来館・成約は CRM の lead_id で追う。媒体／GA4／CRM は帰属期間と定義が異なるため、「Dolphin CREATE の直接紐付け実績」「媒体報告値」「GA4値」を別に表示し、推定を実績と混ぜない。

### テーブル
全テーブルに `facility_id` を持たせ、行ごとのアクセス制限をかける。入力・モデル・プロンプト・出力の版を記録する。

- 第2版から：`facility`、`consent_record`、`consultation_session`、`transcript_segment`、`customer_insight`、`visual_survey`、`crm_lead`、`funnel_event`、`venue_claim`、`asset`、`audience_insight_aggregate`、`creative_version`、`campaign_mapping`、`media_daily_metric`、`approval_audit`
- 第3版で追加：`app_user`、`user_facility_role`、`auth_audit`、`import_job`、`competitor_account`、`hashtag_suggestion`、`report_note`、`market_report`

## 7. 計算と判定のルール

| 指標・判定 | 定義 |
|---|---|
| CTR／クリック率 | クリック ÷ 表示回数 |
| CPC／クリック単価 | 使用額 ÷ クリック |
| 獲得率 | 獲得数 ÷ クリック |
| 獲得単価 | 使用額 ÷ 獲得数 |
| 予約単価／有効予約単価 | 使用額 ÷ 総予約／有効予約 |
| LP予約CVR | 予約完了 ÷ LPセッション |
| 来館率 | 来館 ÷ 有効予約 |
| 来館後成約率 | 成約 ÷ 来館 |
| 成約単価（成約CPA） | 使用額 ÷ 成約 |
| 粗利ROAS | 帰属粗利 ÷ 使用額 |
| 計測紐付け率 | 広告起点と判定できた予約 ÷ 全予約 |
| 分母が0 | 「算出不可」と表示（0や空欄にしない） |
| 金額 | 円未満切り捨て。Fee込みは 使用額 ×（1＋Fee率）。Fee率は施設ごとの設定（初期値20%） |
| 分析の確度 | 最小母数（初期値10・設定可）未満は「参考外」、30未満は「低」、以上は「中」。「高」は付けない |
| 継続／修正／停止／保留 | 来館8件未満は保留。成約0件は停止候補。来館率60%未満は修正。成約単価が平均の85%以下は継続、130%超は修正。自動では反映しない |
| 広告の診断 | CTR高・予約低→広告/LP/フォームの整合。予約高・来館低→低意向予約/追客。来館高・成約低→価格説明/競合比較/接客。成約高・粗利低→値引き・原価 |
| ファネルの詰まり | 段階の通過率が目安の80%未満 |
| 検索語句の除外候補 | クリック3件以上・獲得0件（除外の判断は担当者） |
| DMGの年齢の偏り | 表示の50%超が55歳以上のとき注意を表示 |
| 好調画像 | DMGで獲得数が最多の画像（同数ならクリック率が高いもの） |
| 改善画像 | 画像を使う広告のうち、クリック率0.3%以下、またはクリック数が一桁。該当がなければ「なし」 |
| 差別化候補 | 自社で成約率を押し上げ（平均差＞0・最小母数以上）、競合の発信率が15%未満のテーマ |

予約の有効/無効の条件、売上・粗利の確定時点、対象期間、タイムゾーン（Asia/Tokyo）、帰属ルール、更新時刻、遅延・欠損件数を画面に明示する。

## 8. 媒体別の広告制作

### 8.1 作成の考え方
すべての案に、次の①〜⑤の根拠を付ける。
1. データから導いたターゲットと、ターゲットがよく口にする来館・成約の理由
2. ターゲットが好むビジュアル
3. 会場の強みを活かした画像とキャッチ
4. 競合との差別化、競合より選ばれる理由（ベネフィット）が伝わるキャッチと画像
5. 広告レポートで効果の高いクリエイティブ

### 8.2 媒体ごとに作るもの

| 媒体 | 作る内容 | 主な検証 |
|---|---|---|
| Google検索 | ターゲット検索案（キーワード・マッチタイプ・除外語）、見出し3〜15件（半角30）、説明文2〜4件（半角90）、パス（半角15）、対応LP、画像選定 | 地域・会場種別・証拠付き価値・予約導線。文字数は接続時にAPI仕様で再検証。画像アセットに生成画像を使わない |
| Googleディスプレイ・DMG | 認可済み画像、短文・長文、ロゴ、比率別素材（1.91:1 ほか） | 施設の実景と生成イメージの混同を防ぐ |
| Instagram | 訴求ターゲット、画像選定、静止画・カルーセル、画像内キャッチ・サブコピー・主文・見出し・CTA、ハッシュタグ3個以内、配置別の安全領域 | 画像とコピーを1つの訴求に統一。来館後の期待値との整合 |
| YouTube | 形式と尺（縦型ショート・インストリーム・バンパー）、冒頭のフック、シーン構成、字幕、音源、CTA | 動画素材と音源の権利、完視聴率と予約品質 |
| TikTok（拡張） | 冒頭の訴求、場面・字幕・音声・CTA | 同上 |

画像選定では承認済みの実写を優先する。Dolphin生成画像は asset_id・生成元・編集履歴・会場の事実との一致・人物/著作物の権利・利用媒体・期限・承認状態を付けて受け取る。生成画像を実際の会場・料理・設備と誤認させない。Instagramのハッシュタグは投稿・流入で検証できる単位でのみ評価し、広告APIが提供しない「タグ別成約」を実績として扱わない。

## 10. ログインとセキュリティ

| 項目 | 本番の設定 |
|---|---|
| ログインID | メールアドレス（推奨）または施設コード＋ID【要確認】 |
| パスワード | 12文字以上。漏えい済みパスワードの一覧と照合して弾く。保管は認証サービスの専用方式（bcrypt・Argon2など） |
| 初回 | 招待メールのリンクから本人が設定 |
| 多要素認証 | 本部管理者・施設管理者は必須。他は推奨【要確認】 |
| ロック | 5回続けて失敗で15分ロック。繰り返すと管理者が解除 |
| 自動ログアウト | 無操作30分、ログインから最長12時間 |
| エラー表示 | どの項目が違うかを出さない |
| 履歴 | 成功・失敗・ロック・権限変更を1年保存 |

**施設ごとのデータ分離**
- サーバーとデータベースの両方で、ログインした人の「見られる施設」以外のデータを返さない。
- 画像は施設ごとの保管場所に置き、期限付きの署名URLで表示する。
- 広告・GA4・Dolphin の接続情報は施設ごとに暗号化して保管し、画面に出さない。
- AIに渡すのは1施設の匿名集計だけ。

## 11. AIに渡す共通ルールと実装プロンプト

プロンプトの固定部分は役割・禁止事項・出力形式とし、施設事実・媒体仕様・価格・権利・閾値は承認済みの設定から毎回渡す。回答はJSON Schemaで検証し、公開判断はシステムと承認者が行う。モデル名は設定で変更できるようにする。

### P0｜共通システムプロンプト
```text
あなたはDolphin CREATEのブライダル広告分析・制作支援AIです。Aはデータと施策効果、Bは表現と制作品質を担当します。入力は目的別の利用同意が確認された匿名データと承認済み施設情報だけです。
ルール：①施設の価格、設備、実績、特典、空き状況を創作しない。②個人の発言をその人向けの広告ターゲティングに用いない。③氏名・連絡先・要配慮情報を出力せず推測もしない。④事実、観測された関連、仮説を区別する。⑤母数、期間、根拠、確度、欠損と偏りを示す。⑥広告文は1案1訴求で、会場の証拠とLPの内容に合わせる。⑦広告公開・予算変更は実行せず、承認待ちの提案とする。⑧入力不足や権利不明はunknownとし、publish_ready=falseにする。指定されたJSONだけを返す。
```

### P1｜Dolphinデータ分析（A担当）
```text
入力：{facility_id, period, consented_sessions, diarized_transcripts, surveys, crm_outcomes, venue_facts, data_quality}。
話者別発言からplanning、priorities、visit_motive、visual_preference、positive_trigger、unresolved_objection、decision_factor、noncontract_reasonを抽出。各項目にsession_id、speaker、start_sec、end_sec、短い匿名化根拠、explicit_or_inferred、confidenceを付ける。本人発言と担当者推測を区別し、成約後の結果から過去の動機を創作しない。
その後、十分な母数のある群だけを集計し、成約群と非成約群の各傾向についてn、成約率、比較基準、期間、欠損率、偏りを出す。因果関係は断定せず、会場・広告・LP・接客それぞれで検証できる仮説を最大3件提示する。
出力JSON：{insights:[],segment_comparisons:[],strengths:[],unresolved_issues:[],personas:[],hypotheses:[],limitations:[],blocking_issues:[]}。
```

### P2｜媒体別クリエイティブ生成（A＋B担当）
```text
入力：{step1_target_and_voice, step2_preferred_visuals, step3_approved_venue_claims, approved_assets, step4_competitors, differentiation_candidates, step5_ad_performance, landing_pages, media_specs, budget_cap_month}。
媒体別に作り分ける。
Google検索広告：ターゲット検索案（ターゲット・検索意図・キーワードとマッチタイプ・除外語）、テキスト案（見出し・説明文を媒体仕様内で複数）、画像選定（承認済みの実写のみ）。
Instagram広告：訴求ターゲット、画像選定（ビジュアルアンケートの根拠付き）、広告クリエイティブ案（画像内キャッチ・サブコピー・主文・見出し・CTA・ハッシュタグ3個以内）。
YouTube広告：動画の内容と方向性（形式と尺、冒頭のフック、シーン構成とテロップ、音源、CTA）。
作成の考え方：①データから導いたターゲットと、ターゲットがよく口にする来館・成約の理由 ②ターゲットが好むビジュアル ③会場の強みを活かした画像とキャッチ ④競合との差別化、競合より選ばれる理由（ベネフィット）が伝わるキャッチと画像 ⑤広告レポートで効果の高いクリエイティブ。各案のwhyに①〜⑤の根拠を入力の数値と声を引用して書く。
各案にclaim_ids、asset_ids、hypothesis、main_kpiを付ける。承認外の事実、実際と異なる施設画像、誤認させる人物体験談、競合の画像・会場名を使わない。小標本の実績を根拠にしない。条件付きの施設事実は広告文に「※」と条件を入れる。
出力JSON：{google_search_ads:[],instagram_creatives:[],youtube_plans:[],blocking_issues:[]}。
```

### P2c｜キャッチコピー案（クリエイティブ作成）
```text
選んだ画像に重ねるキャッチコピーを5案作る。キャッチは全角15字以内、サブコピーは全角24字以内。1案1訴求で、画像の訴求と一致させる。承認済みの施設事実にない価格・特典・設備・実績は書かない。条件付きの事実を使うならサブコピーに「※」で条件を入れる。ターゲットがよく口にする言葉を活かし、競合との差別化テーマがあれば優先する。
出力JSON：{copies:[{text,sub,f,target,basis}]}。
```

### P3｜画像選定・Dolphin画像連携（B担当）
```text
入力：{creative_brief, visual_survey_aggregate, approved_asset_catalog, dolphin_generated_asset_catalog, rights_and_expiry, venue_photo_references, placement_specs}。
各訴求につき画像候補を最大3点選び、asset_id、選定理由、本人アンケートの集計根拠、実景との一致、権利、媒体ごとのトリミング、画像内文字の余白、要確認箇所を返す。既存素材が不足するときだけ生成指示を提案。生成指示は会場構造や設備を変えず、自然な肌と手指、白いドレスの立体感、抑えた自然光、白飛びなし、過度なオレンジ色なしを指定する。未確認の権利・事実は使用不可。
出力JSON：{ranked_assets:[],image_generation_briefs:[],human_review_points:[],blocking_issues:[]}。
```

### P4｜広告レポートと改善提案（A担当）
```text
入力：{period, attribution_rule, media_metrics, ga4_events, crm_funnel_events, creative_metadata, cost, data_quality, prior_period}。
媒体・キャンペーン・広告・素材別に費用、表示、クリック、LP到達、予約、有効予約、来館、成約、売上、粗利、各単価と率を再計算する。媒体報告CV、GA4、Dolphin CREATEがlead_idで紐付けた実績は別列にする。欠損率、成果反映遅延、サンプル数を示す。
出力順：①事実（前期差）②ファネルの詰まり③解釈と代替仮説④継続/修正/停止/保留の提案⑤次週の一変数テスト。CTRだけで成功と判定しない。成約母数が少ない案は保留し、予算・配信状態を勝手に変えない。

```

### P4b｜予約・来館・成約の原因診断（A担当）
```text
入力：{ga4_landing_page_events, media_clicks, form_events, crm_reservations, qualified_leads, visits, contracts, cancellation_reasons, consultation_insights, attribution_rule, data_quality}。
媒体別・LP別・広告別の広告クリック→LPセッション→CTAクリック→フォーム開始→予約完了→有効予約→来館→成約の人数/件数と段階別率を計算する。未結合・成果未確定は別枠に出し、同一lead_idの重複予約を排除する。落差が大きい段階ごとに、観測事実、最大3つの原因仮説、確認すべきイベント/発言根拠、改善案、次回テストの主指標を提示。媒体CVとCRM成約を混同しない。少数件で断定しない。
```

```text
事実の裏付け、費用や特典条件の抜け、媒体仕様、実写/生成の区分、素材権利、広告とLPの一致、予約導線、計測URL、期間と予算を検査。各問題にseverity、location、evidence、required_fixを付ける。blockerが1件でもある、または施設承認がない場合はpublish_ready=false。公開APIを呼ばず検査結果のみをJSONで返す。
```

## 12. 計測の実装

GA4 のイベントをLPと予約フォームに設置する：`page_view`／`session_start`、`view_fair`（フェア詳細表示・独自イベント）、`select_fair`（CTAクリック）、`form_start`、`form_error`、`generate_lead`（予約完了）。`lead_id` はサーバー側でCRMと結合し、GA4へ氏名・メール・電話などの個人情報を送らない。来館・成約はCRMの確定イベントを主データとする。`view_fair` 等は製品側で定義するカスタムイベントであり、GA4の自動収集ではない。「広告クリック」と「LP内のCTAクリック」は別の指標として表示し、GA4セッション数と媒体クリック数の一致を前提にしない。

## 13. 実装の段階と受入条件

**第1段階**：1施設で、ログインと施設ごとのデータ分離、Dolphin CSV／JSON、予約・来館・成約CSV、Google広告／Meta／GA4の実績（まずCSV、権限が用意できた媒体からAPI）を結び、5メニューと手動承認つきの広告案、月次レポート出力を運用する。既存データでIDの結合率と同意範囲を検証する。

**第2段階**：Dolphin API／Webhook（接客データ・生成画像・マーケットレポート）を接続する。Google広告／Metaへの承認後の入稿、予算上限、緊急停止、重複防止、配信エラーの再処理を実装する。GA4の予約完了を検証し、必要に応じてCRMの後工程イベントを連携する。⑩の返却をAPI化する。

**第3段階**：Googleのリード向け拡張コンバージョン、Meta Conversions API の適合を確認し、許諾済みの成果のみ媒体へ返送する。複数施設の比較、A/Bテスト、入札・予算提案を拡張する。媒体ごとのAPI審査・権限・仕様・測定期間は接続時に確定する。

**受入条件**
1. 主要インサイトに発言根拠と確度がある
2. 個人情報が広告生成の入力に混入しない
3. 素材・事実・LP・予算が未承認なら公開できない
4. 同じ送信で広告を重複作成しない
5. テスト予約が lead_id で来館・成約まで追える
6. 媒体値と Dolphin CREATE 実績の違いが表示される
7. 施設間の閲覧が遮断される（本番設計の受入テスト10項目をすべて通す）
